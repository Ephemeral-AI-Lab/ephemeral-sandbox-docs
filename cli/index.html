Quick start

From checkout to first command

Run Docker Desktop first. The gateway launcher builds the host clients, rebuilds the Linux daemon, starts in the background, and creates the shared private token.

01

Expose repo tools

Add the checkout's bin directory to this shell. After this export, use sandbox-manager-cli directly—without a bin/ prefix. Repeat the export in each new terminal.

Shell
cd /Users/yifanxu/Ephemeral-AI-Lab/ephemeral-sandbox
export PATH="$PWD/bin:$PATH"
02

Start the gateway

The launcher returns after starting the gateway in the background. Its wrappers read the generated token automatically.

Build and start
start-sandbox-docker-gateway --rebuild-binary
03

Use the clients

Create a sandbox, capture its id, then run a command against that sandbox scope.

First sandbox
SID=$(sandbox-manager-cli create_sandbox \
  --image ubuntu:24.04 \
  --workspace-bind-root /absolute/path/to/project | jq -r '.id')

sandbox-runtime-cli --sandbox-id "$SID" exec_command pwd
PATH is the deciding factor--rebuild-binary builds the three host CLI binaries, but running the launcher cannot change its parent shell's PATH. Export $PWD/bin first, or keep using bin/sandbox-manager-cli.
Built-in reference

Help is always local.

Each executable lists only its own authority set. Use help OPERATION for the exact usage, argument descriptions, defaults, and examples compiled into the current binary.

Common mistakeRuntime's global --sandbox-id appears before the operation. Management and Observability operation flags appear after it.
Help commands
sandbox-manager-cli help
sandbox-runtime-cli help
sandbox-observability-cli help

sandbox-manager-cli help create_sandbox
sandbox-runtime-cli help exec_command
sandbox-observability-cli help snapshot
Process contract

Stable channels and exits.

Automation can branch on the process exit code and parse the documented channel as one JSON line.

Exit 0

Operation success

One compact operation-result JSON line on stdout. Help also exits 0 and writes human-readable text to stdout.

Exit 1

Remote failure

Gateway operation, connection, or response-protocol failures write one structured error envelope to stderr.

Exit 2

Local usage failure

Argument, scope, projection, or gateway-configuration failures are rejected locally and written to stderr.
