# Phase 1 — Non-live selection, implementation, and qualification

Execution status: **1A `H_PROFILE` `NOT_RUN`; accepted joint, architecture, and
physical-method winners: 0**

## Objective

Under one explicitly non-live and discardable authorization envelope:

1. select one complete compile-valid topology × physical profile as
   `H_PROFILE`, or stop with `NO_WINNER`;
2. implement and accept the canonical format, offline selected-state behavior,
   and permanent application/current-Linux integration in that order;
3. add a temporary migration unit whose only dependencies are the inventoried
   read-only legacy adapter, accepted pure canonical functions/types, and the
   narrow selected-state import command, then seal exact `H_PRECUTOVER`; and
4. independently qualify and rehearse byte-identical `H_PRECUTOVER`.

The old architecture-first/method-second split is removed. Physical
representation can change dependency, helper, process, recovery, and resource
needs, so architecture and method must survive as one realized pair. The whole
phase remains reversible by rejecting or discarding non-live artifacts. It may
create isolated V2 test state, source, builds, and evidence, but it may not
route, select, or acknowledge V2 as live truth.

Terms such as **selected-state behavior** and **current runtime-effect owners**
name required behavior and observed ownership only. They do not preselect an
aggregate storage/runtime subsystem, crate, trait, seam, component, service,
process, deployable, or count. Exact topology is an output of 1A. `Hstore` is
only the stable acceptance-record label for gate 1C; it does not require an
aggregate storage object, port, component, or boundary.

R0 has zero mandatory new components, traits, ports, facades, registries,
packages, processes, or deployables. Algorithms, codecs, hashes,
canonicalization, and validation remain pure functions in a lawful existing
caller unless a presealed executable necessity trigger proves that exclusive
state, lifecycle, synchronization, privilege, or resource custody requires a
new owner. A semantic role never creates a source or deployment boundary by
itself.

## Predecessor output consumed

Phase 1 consumes the independently accepted, content-addressed Phase 0 seal:
requirements and MCTS scope; total transport-aware external-surface, field,
writer, authority, process, and deployment facts; independent oracle; the
finite topology and physical-method
universes, signed cutoff, transform/equivalence/admissibility/dominance rules,
compile-valid evidence-only `R_LEGACY_CONTROL`, and complete generated
selectable product; direct-local-dependency/source-ledger generator; disposable
runtime spikes; resource envelopes; selection corpus and untouched holdout;
matched-comparator eligibility; migration source; and
preregistered numeric, statistical, and invalidation rules.

Without that seal, candidates could omit a pair or consumer, delete
inconvenient behavior, define their own judge, tune on the holdout, or hide an
authority/resource requirement.

## Entry authorization and capability ceiling

- The Phase 0 output is independently accepted, content-addressed, and
  unchanged.
- The owner explicitly authorizes this bounded non-live evaluation/build
  envelope. Phase 0 completion does not self-authorize it.
- The externally pinned per-artifact verifier policy authenticates the
  phase-entry attestation binding the exact authorization receipt; actor
  principal/credential/control-domain triples; exact gate capabilities;
  validity/revocation fact; catalog; gate; and lineage.
- Laboratory code remains disposable and outside production `src/` and
  production dependency graphs until its owning production gate begins.
- Current legacy remains the sole live writable and acknowledging truth.

| Actor | May | Must not |
|---|---|---|
| owner | authorize Phase 1; accept or reject independently reviewed gate records | waive a hard gate, select by preference, or let Phase 1 exit authorize Phase 2 |
| candidate teams | realize isolated joint candidates and later production artifacts; produce raw evidence | alter the Phase 0 universe/judge/holdout; accept their own gate; route or acknowledge live V2 |
| independent gate authorities | reproduce manifests, generators and compiles; run or audit frozen gates; accept a hash or `NO_WINNER` | rebuild qualifying bytes, promote partial scope, or silently change a predecessor |
| current operators/writer authorities | support isolated shadow/rehearsal and prove fencing behavior | install a live V2 route, make V2 writable, or emit a live V2 acknowledgment |

Every promotion stays below one capability ceiling: non-live work whose failure
leaves current live truth unchanged. A signature proves exact bytes and
evidence; it grants no live-fleet authority.

## Six ordered gates, one non-live phase

```text
1A joint topology × physical profile H_PROFILE or NO_WINNER
  -> 1B H_FMT naming exact H_PROFILE
  -> 1C Hstore naming exact H_FMT and H_PROFILE
  -> 1D Hpermanent naming exact Hstore
  -> 1E H_PRECUTOVER naming every exact prior hash
  -> 1F Hqual naming byte-identical H_PRECUTOVER
```

Each gate has its own producer, independent acceptor, evidence scope, hash,
stop conditions, and invalidation edge. A successor begins only after its
predecessor passes. Any consumed byte or decision change invalidates that gate
and every transitive consumer. `NO_WINNER` at 1A closes 1B–1F and Phase 2.

These are gates, not phases, because none expands the actor capability ceiling
or changes the legal rollback class. Hashing prevents evidence laundering
without manufacturing more top-level authorization events.

## 1C — Offline selected-state qualification: `Hstore`

1. Bind every physical record, identity assumption, recovery rule, and test to
   exact `H_FMT` and `H_PROFILE`. Implement only inventory-justified semantic
   aggregates and bounded queries: revisions, OCC transitions, exact replay/

   Physical records and recovery contain no current runtime-effect or
   application policy unless `H_PROFILE` assigns co-location and proves that

2. Implement the one accepted durability, lookup, selection, reachability,
   replacement, reader-retirement, backup, and startup-recovery profile. Add no
   runtime strategy menu, hidden database/WAL, persistent cache/refcount, or
   second selector.
3. At candidate-bearing admission, prove exact canonical-byte equality for an
   occupied candidate `StateId`. A reference-only transition consumes only a
   previously admitted authorized no-alias binding and must not receive or
   reread candidate payload. Then prove for every accepted no-alias checkpoint,
   reference-only fork, rollback-to-existing, `commit_fork`, and
   same-state move across success, conflict, stale parent, duplicate, cancel,
   timeout, crash/restart, recovery, root deletion, and last-reference races:

   ```text
   total selected-state immutable payload bytes read    = 0
   total selected-state immutable payload bytes written = 0
   total selected-state immutable payload bytes copied  = 0
   new root-private physical closure bytes              = 0
   ```

   Independently force unequal canonical bytes under one candidate digest
   through publication, import, recovery, index rebuild, reference-API ingress,
   and last-root races. Candidate-bearing reference requests must be rejected

   `T03_REJECTION / STATE_ID_COLLISION` before any

5. Inject filesystem/barrier/torn/corrupt/ENOSPC cuts and execute the complete

## Deliverables and exit

Exit requires independently accepted unchanged `H_PROFILE`, `H_FMT`, `Hstore`,
`Hpermanent`, exact `H_PRECUTOVER`, and `Hqual` in order. Every hash names its
exact predecessors; `Hqual` qualifies byte-identical `H_PRECUTOVER`; the live
V2 acknowledgment count is zero; and all producers, raw evidence, generated
ledgers, deletion manifests, runbooks, monitors, rollback criteria, resource
bounds, and invalidation owners are retained.

The owner may then decide whether to issue a separate Phase 2 authorization.
Phase 1 exit does not issue it. Compatibility retirement, release, and any
legacy deletion remain closed.

## Stop

Stop on `NO_WINNER`; late eligible discovery; generator/hash drift; stale
topology; unresolved cost/fault cell; compile failure; premature holdout access;
evidence-scope promotion; unbounded decoding/resource use; a second truth or
selector; permanent-V2 dependency on temporary migration code or a legacy
adapter; unmapped root; stale-capable writer;
writable dual truth; generation reuse/decrease; containment/capacity failure;
failed hard gate; incomplete monitoring; restore uncertainty; or any live V2
route, selection, or acknowledgment. Return changed input to its owning gate
and invalidate every transitive result; never patch a sealed artifact in place.
