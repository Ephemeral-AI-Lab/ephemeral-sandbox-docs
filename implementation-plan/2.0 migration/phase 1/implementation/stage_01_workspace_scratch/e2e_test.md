# Stage 01 E2E — Workspace-scoped execution scratch

Links: [implementation overview](../index.md) · [stage specification](spec.md) · [quantitative contract](../../prep/04-seqcdc-space-time-complexity-and-acceptance-criteria.md)

Tier: **POC proof tier**. Required now: one focused packaged lifecycle case, one primary restart/unsafe-reap case, and the tiny paired benchmark/memory sentinel. Broad regression and normative qualification are Stage 07 work.

## 1. Stage-local test objective

Implementation execution is blocked unless the product worktree is on the
exact fresh branch `upgrade-2.0-phase-1`, created from the newest approved
immutable product revision, with its base commit, upstream, clean scoped
worktrees, and responsible implementer recorded before any code edit. This
planning stage creates or switches no branch; any mismatch is a hard blocker.

The test must falsify the risks created by moving transcripts: wrong-session routing, execution-ID collision after restart, recursive deletion while a command or terminal record still owns a file, unsafe legacy cleanup, unbounded retained resources, and an accidental command/PTY regression. It is runnable immediately because command admission, workspace sessions, public CLI execution, Docker gateway custody, snapshots, and outside storage inspection already exist.

Invariants:

1. Every new transcript route is `workspace_scoped`, and its path is contained by the admitted workspace session.
2. Implicit, explicit, concurrent, terminal-retained, cancelled, and restarted commands never mix transcripts or cross-delete.
3. Active commands are rejected/cancelled/joined and terminal owners/FDs reach zero before recursive workspace deletion.
4. The legacy global root receives zero new entries; the compatibility reaper touches only validated stale entries in a bounded batch.
5. `/workspace`, CLI responses, legacy LayerStack v1 authority, and native execution are unchanged.
6. Logical ownership returns to warmed idle; the short physical-memory sentinel respects the Stage 01 ceilings.

Authoritative behavior is public CLI/gateway command execution and workspace lifecycle. Outside `/eos` inspection proves placement/allocated bytes but does not replace CLI assertions. Required structured fields are `scratch_route`, hashed session/execution IDs, active/terminal owners, open transcript FDs, reaper counts, cleanup state, and quiescence duration. CDC/CAS, candidate comparison, activation, publication, packs/GC, squash, mixed roots, and final performance/portability matrices remain deferred.

## 6. Tiny correctness and benchmark loop

Use `workspace-scratch-tiny.yml` with seed `0x5A01`, Ubuntu 24.04 pinned OCI index and resolved arm64 platform digest, one warmed long-lived packaged daemon, the same filesystem, and alternating `control,candidate` order. The control is the behavior-compatible legacy locator adapter built in the same revision; it is not a prior binary with unrelated changes.

Corpus: empty/no-op; a localized 1 KiB edit in deterministic 1 MiB content; deterministic 1 MiB incompressible content; 256 small files totaling ~1 MiB; repeated overwrites at depths 1, 8, and 32. Run 2 warmup pairs and 6 measured alternating pairs (12 lifecycles), including one candidate cancellation cycle. Preserve raw per-pair JSON; report absolute values and ratios, but make no p95 claim from six samples.

Exact diagnostic caps: whole run ≤60 s; every individual operation ≤60 s; candidate/control median no-op alert at `+3% + 0.5 ms`; throughput alert below 97%; candidate peak RSS ≤384 MiB and ≤128 MiB above idle. These are POC stage gates/alerts, not a claim of final normative p50/p95 qualification. Any correctness mismatch, global write, limit breach, or positive live-resource residual blocks.

Record `elapsed_ns`, `output_digest`, per-subtree logical/allocated bytes, transcript bytes/count, active/terminal owners, FDs, tasks, queues, mappings, permits, RSS/cgroup scopes, cleanup latency, first/last settled delta, and robust Theil–Sen slope. Every field carries `measured`, `derived`, `estimated`, or `unknown`.

## 7. Memory-stability and reclamation test

This stage changes path allocations, execution-lease/terminal-record cleanup, FDs, teardown tasks, and the boot reaper. The tiny case is therefore also the required sentinel. Do not restart the daemon between measured cycles; restart occurs only in the separate restart case.

Sequence:

```text
idle baseline -> 2-pair warmed idle -> 12 active peaks
-> bounded product-observable quiescence after each -> first/last settled windows
```

Before candidate data is inspected, freeze the noise band from the six control settled deltas as `max(8 MiB, control median absolute deviation × 4)` and record it in the preset artifact. Poll every 100 ms for at most 5 s; quiescence requires active leases, terminal owners for destroyed sessions, transcript FDs, teardown tasks, reaper task, queue items, and permits at warmed-idle values. No arbitrary sleep, restart, purge, `malloc_trim`, or allocator change is permitted.

Logical verdict: changed live resources are `bounded-and-released`; bounded terminal state is `bounded-retained-by-design` only inside its declared cap and is zero after session destroy. Physical verdict: RSS/cgroup ceilings hold and post-warmup settled slope is not positive beyond the frozen band. Attribute anonymous/file-backed/page-cache effects. `suspected-leak`, `confirmed-leak`, or missing stage-gating data blocks; RSS flatness cannot excuse growing live gauges. The full 64 MiB/256 MiB/1 GiB × 1/16/64 history matrix and sustained lifecycle campaign are deferred to Stage 07.
