Architecture/Components
Act 04 · Responsibilities

Every durable byte has one owner

MPLA is less a monolith than a set of narrow authorities: workspace mutation, payload placement, canonical construction, ref visibility, projection acceleration, and resource supervision.

No component may infer authority from a pathname. Allocation IDs, owner epochs, receipts, generations, and leases make ownership explicit.

Many-small-file path

Disk-backed streaming replaces repository-sized maps

One million paths are handled as bounded sorted runs, then merged with fixed fan-in. Memory holds cursors and buffers, not one task, descriptor, or heap object per path.

Naive per-file designMPLA streaming designWhy it matters at 1M files
One in-memory record/task per entryBounded run buffer + disk spoolHeap follows configured permit, not file count
Many simultaneously open filesBounded descriptor windowAvoids FD exhaustion
Random metadata/object writesOrdered grouped recordsBetter sequential I/O and fewer sync boundaries

Global limits

Scheduling, recovery, and accounting surround every heavy job

Memory safety comes from admission control and shared permits—not from hoping each component independently stays small.

Portability seam

The adapter proves semantics before it accelerates anything

Boot qualification rejects an environment before mutation if it cannot support stable allocation, durable sealing, writer revocation, required metadata, or the chosen mount semantics.

ProbeEnvironment qualifier

Kernel, filesystem, mount namespace, upper/work placement, xattrs, whiteouts, durability.

ContractProjection adapter

Select or build a root realization; return a verified immutable receipt and holds.

ExecuteWorkspace adapter

Create the private merged view, expose readiness, and prove teardown removed mounts and leases.

Easy to replace does not mean trivial to replace. A microVM or WASI adapter still needs semantic equivalence tests. What becomes easy is that it need not rewrite the canonical or payload model.
