Architecture/Evidence
Act 07 · Falsification

Measure the boundary the user actually waits for

The PoC separates warm selection from cold construction, application heap from kernel memory, and response time from final settlement. It is designed to disprove the architecture quickly.

Two suites: smoke stays below three minutes for iteration; heavy stays below ten minutes and never uses more than a 10 GiB fixture envelope.

Decision rule

Performance is considered only after correctness passes

The PoC emits a verdict ledger instead of averaging incompatible successes and failures into one score.

Qualify

Host, backend, OverlayFS, cgroup, durability, metadata semantics.

Prove semantics

Independent root oracle, exact owner, old-or-complete-new recovery.

Prove bounds

Memory, FDs, mounts, queue, storage categories, unexplained bytes.

Measure

Raw samples, p50/p95/p99, CPU, I/O, amplification, hit status.

Compare

Matched current controls and identical timed boundaries.

Decide

Adopt, optimize, or reject the architecture with the failing gate named.

Experiment-ready, not implementation-ready. The design is detailed enough for a focused PoC. The PoC’s job is to settle stationary adoption, memory/metadata scaling, cold-path honesty, and crash correctness before production migration begins.
